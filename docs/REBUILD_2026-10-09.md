# Rebuild 2026-10-09 — making the code match the report

Scope: re-implement the architecture the report describes, retrain and re-measure.
This document is a software + experiment record. Every number below is produced by
a command that actually ran on this workstation; nothing is hand-entered.

## What changed in the code

| Report claim | Before (old code) | After (this rebuild) |
| :-- | :-- | :-- |
| Mamba-3 selective SSM | `Mamba3Block` was **Mamba-1** + input RoPE + gate | Native `mamba_ssm.modules.mamba3.Mamba3` (`hdml/models/mamba3_native.py`), built-in rotary state-space embedding + trapezoidal discretisation |
| Flow-Matching action policy | `flow_policy` defined but never trained; real policy was an MLP head | Flow Matching over an action chunk is the trained policy (`sample_deterministic`, Euler solve) |
| Action chunking `k=5` | config `chunk_size: 4` | `chunk_size: 5`, chunk targets built in both datasets |
| HiQC critic + PAVE + Grad-CAPS | `HDMLLoss` never called; all frozen | Wired into `HDMLTrainer._compute_loss` with configurable weights |
| Two-tier macro/micro control | `macro_interval != 1` raised; `act_from_subgoal` rejected | `act_from_subgoal` implemented; two-tier path enabled |
| `hdml/models/liquid_head.py` | CfC on a raw chunk, residual on `actions` | CfC filters the single executed action |

## Latency (fresh, synchronised)

`python scripts/measure_closed_loop.py --checkpoint checkpoints/rebuild/halfcheetah_v5/best_model.pt`
→ `results/rebuild_final/latency.json`.

| Quantity | Before optim | After optim |
| :-- | --: | --: |
| Pure model inference (GPU) | 16.27 ms (61.5 Hz) | **7.25–8.45 ms (118–138 Hz)** |
| Closed-loop control cycle | 17.35 ms (57.6 Hz) | (to re-measure) |

The dominant latency bug was in `HDMLModel.get_action`: it ran the flow sampler and
the CfC filter over **all 20 context steps** on every control step, although only the
last step's action is executed. `encode(action_last_only=True)` now runs the flow+CfC
branch only on the last step. Backbone cost is unchanged (~5.1 ms for 3 Mamba-3 layers).

Other throughput fixes (training): removed a second backbone forward pass per step (the
critic bootstrap uses the return-to-go target); `epoch_losses` accumulate detached GPU
tensors instead of calling `.item()` 9×/step; PAVE (double backward) runs every
`pave_interval=4` steps; batch size 256 → 512. Net ~4,600 → ~10.5 batch/s at bs=512.

Note: native Mamba-3 has no CPU path (Triton/CUDA only), so the poster's "CPU 5.38 ms"
would need the portable ONNX path. ONNX export of the native model currently fails in
the Triton RMSNorm kernel (`invalid operands of type pointer<int64> and int32`) — the
Triton kernel is not torch.onnx-traceable. A portable implementation would be required,
so the CPU number is unavailable and must not be quoted.

Poster charts (`KH_thi_KHKT_TP_2026-2027/poster_assets/chart_*.png`) originally carried
numbers absent from every log (IQM 82.4 for HDML, P(HDML>…) 96.8%, CPU 5.38 ms) and were
not traceable to any run. They were backed up to `_OLD_unverifiable/` and replaced with
charts drawn from `results/rebuild_final/benchmark_halfcheetah-v5.json` by
`scripts/make_poster_charts.py` (outputs in `poster_assets_from_logs/`).


## Comparative benchmark (5 episodes, seed 42)

Log: `results/rebuild_final.log`, `results/rebuild_final/`.

> Two bugs were found and fixed during the rebuild: (1) an action-chunk loss weight
> that under-weighted the flow policy, and (2) a flow-prior mismatch (training used a
> Gaussian prior, the first sampler used a zero prior). After the fix the reward rose
> from IQM 0.84 to ~15–23.

Perturbation: HDML IQM 1.23 [0.44, 2.49], episode completion 100%. Because the flow
policy samples from a Gaussian prior, closed-loop results fluctuate between runs
(IQM 15–23 across repeats); a fixed evaluation generator would remove this.

## Honest reading of the result (negative results reported)

1. **Reward claim does NOT hold**: HDML IQM ≈ 15–23 is below both DT (95.60) and RNN
   (45.27). The report's "IQM 88.09, 16× DT" is **not reproduced**. The flow policy is
   undertrained at 3 epochs on this task.
2. **Smoothness claim partially holds**: HDML jerk 0.60 is lower than DT (0.81) in this
   run but higher than Decision RNN (0.48); it is not consistently the best.
3. The old report numbers (jerk 0.7862, IQM 88.09 / 18.88) were not reproducible even
   before this rebuild (see `results/recheck_20261008/BIEN_BAN_KIEM_CHUNG.md`).
